# FlowDay

一个可以直接运行的中文日常规划原型。React + Vite，浅色设计，桌面优先，支持基础手机布局。

## 启动

需要 Node.js 22.12+（本次验证使用 Node.js 24）。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。Windows 也可以双击 `Start-FlowDay.cmd`。端口已被占用时不会悄悄切换到其他端口，以免看起来丢失本地数据。

```sh
npm test
npm run build
npm run preview
```

## 可以体验什么

- **今天**：按日期查看时间轴，筛选固定/未完成任务，勾选完成、设置精力，查看专注时长和周目标。
- **日历**：日、周、月切换；周视图将弹性时间块拖到另一日期或时间，按 15 分钟对齐；固定和已完成时间块锁定。手机端可在详情中修改时间，周网格支持横向滚动。
- **任务**：Inbox、已计划、已完成；搜索、分类过滤、优先级、预计时长、截止日期、精力需求、标签、关联项目和清单。右侧详情支持安排到空闲时间。
- **目标**：从关联任务的完成记录计算目标进度、阶段里程碑和本周实际完成时长。
- **复盘**：选择日期查看统计，记录心情、阻碍、反思和明日建议；自动保存。
- **洞察**：7/14 天专注与完成率趋势、学习/运动连续天数、每日精力热力图、分类时间分布及规则生成的文字总结。
- **快速添加**：`Ctrl/Cmd + K`；可输入“明天下午做两小时产品设计”“每天晚上安排两小时健身”，核对并修改解析结果后保存。
- **动态调度**：插入临时固定事件时先预览受影响任务；按优先级和截止日期，在 08:00–23:00、未来 7 天内寻找完整空档；接受后才应用。无法安排的任务会明确提示，不会被丢弃。
- **45 分钟推荐**：同时考虑可用时长、当前精力、优先级、截止日期；可开始真实专注计时，刷新仍会继续。

## 撤销与备份

顶部提供撤销、重做与“数据与备份”入口。新增、修改、完成、重排以及恢复/清空支持本次打开期间最近 30 步撤销；刷新或开始/结束专注会清除操作历史，防止恢复旧计时。

“数据与备份”可导出 JSON 文件、选择文件校验并预览后恢复。恢复是替换整个空间，不是合并；最大文件 5 MB，损坏、版本不匹配或字段不完整的文件会被拒绝。正在进行的专注不写入备份，已结束的专注记录保留。恢复后沿用原有每日重复规则，在下次加载时补齐未来任务。

清空需输入“清空”。清空或恢复前自动保存当前空间到 `flowday.recovery.v1`，之后可通过“找回上次替换前的数据”恢复，刷新后仍可用。快照保存失败时停止替换。快照只保留最近一次且与当前数据同属浏览器存储，重要数据请下载备份；清理网站数据会同时删除本地快照。专注进行期间暂停恢复、清空和撤销/重做。

本轮在独立测试端口验证了新增 → 撤销 → 重做、导出文件 → 文件预览恢复 → 刷新保留、清空 → 刷新 → 本地快照找回及无效备份拒绝。补充测试覆盖历史上限、计时边界、备份往返、重复记录和存储失败保护。

## 本地数据结构

目标页支持创建和编辑名称、分类、描述、每周投入及 1–12 个里程碑。任务页的“批量管理”支持多选后关联目标、改期、删除；修改作为一步记录，可整体撤销。改期先预览，保留已计划任务的时刻，Inbox 从 09:00 起寻找空档，遇到冲突或截止限制时整批停止。固定、已完成和正在专注的任务不能批量改期。

重复任务删除可选择仅所选课次或本次及以后。前者记录跳过日期，后者保存停止日期，刷新和备份恢复后均不会重新补回被删除的课次。批量改期、关联目标只影响所选任务，不改未来重复模板。

数据存于当前浏览器、当前网站地址的 localStorage，键名 `flowday.v1`，带 `version: 1`。初次进入为空白状态，不预置任务、目标或历史统计。旧演示工作区会一次性重置为空白，并在浏览器本地保留重置前备份；之后新增的记录不受影响。没有网络同步或真实 AI 调用，也没有外部字体依赖。

| 实体           | 字段与用途                                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tasks`        | UUID、title、category、priority、duration、energy、kind、date、start、done、actual、deadline、tags、checklist、projectId、repeat、seriesId、occurrenceDate |
| `projects`     | 目标/项目 ID、名称、分类、周时长目标、阶段里程碑                                                                                                           |
| `energy`       | 日期 → 1–5 分精力记录                                                                                                                                      |
| `reviews`      | 日期 → 心情、最大阻碍、反思、更新时间、复盘状态                                                                                                            |
| `focusLogs`    | 日期、任务 ID、分钟数、来源（计时）                                                                                                                   |
| `focusSession` | 正在专注的任务及开始时间戳                                                                                                                                 |
| `recurrences`  | 独立重复模板；移动或修改某一次任务不会改变后续默认时间                                                                                                     |

日期采用本地 `YYYY-MM-DD`，开始时间采用当日分钟数。任务与时间块暂时是同一个实体，通过 `date/start` 是否为空区分 Inbox 与已安排任务。状态和统计逻辑集中于 `src/model.js`、`src/store.jsx`，以后可替换存储层接数据库。

## 当前实现边界

- 自然语言使用本地常见表达规则，不是通用语言理解；保存前有可修改的解析预览。
- 每日重复预排未来 30 天，打开应用时补齐；编辑只影响当前一次。后续重复任务遇到冲突会寻找稍后空档，无空档时进入 Inbox，并注明原定日期。
- 自动调度不拆分任务；不会自动挪动固定或已完成事件；专注时长按完整分钟计入结束当天。
- 标为完成时，实际用时初始取预计时长；可以在已完成任务详情中校正。专注计时独立统计，不代表任务已完成。
- 目标百分比按截至今天的关联任务及 Inbox 任务计算，未来重复任务不会稀释当前进度；里程碑按自定义阶段数量等分完成比例。
- localStorage 数据仅在同一浏览器和地址下保留。清理站点数据或更换端口会使用另一个存储空间。尚未实现账号、多设备同步、云备份、系列批量编辑、真实触屏拖拽。

## 验证

`npm test` 当前 35 项测试覆盖中文解析、跨月日期、重叠判断、固定事件保护、截止限制、无可用空档、重复任务幂等、精力推荐、目标/复盘联动、撤销与备份、批量改期原子性、重复删除及恢复等。

在 Codex 内置浏览器验证了六页切换、自然语言新增、跨日期拖拽、临时固定事件重排、Inbox 安排、任务完成、清单与标签保存、复盘刷新恢复、真实专注计时和手机布局。桌面检查 1440×1000，手机检查 390×844。视觉沿用原对话的文字规范与重建首页基准；原对话的六张图片未能从会话读取，因此不宣称逐图复刻。

首页基准和实际截图已做视觉对照：固定导航、标题层级、圆角卡片、分类配色、时间轴和右侧状态栏保留一致的结构。日期、统计数字、头像和任务时间使用真实本地状态；标题与主要入口文案沿用基准。修复了短任务相邻覆盖、标签输入、详情保存状态和提前/深夜任务显示范围。最终 22 项逻辑测试及生产构建通过，复测未出现新的控制台错误或整页横向溢出。
